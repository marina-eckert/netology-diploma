# Диплом Fullstack JavaScript

Полноценное SPA для поиска и бронирования книг в библиотеках Москвы. Создано с нуля по [заданию Нетологии](https://github.com/netology-code/fsmidjs-diplom) и переданному макету Figma.

**Развёрнутое приложение:** [netology-diploma.onrender.com](https://netology-diploma.onrender.com/).

Приложение размещено на Render, база PostgreSQL - в Neon.

## Возможности

- Каталог, поиск по названию и автору, выбор библиотеки, фильтр доступности, пагинация.
- Подбор книг на период аренды, карточка книги с обложкой и описанием.
- Регистрация, вход и выход с Passport и серверной cookie-сессией.
- Читатель: бронирование, отмена, история и редактирование профиля.
- Администратор: создание, редактирование и удаление книг, библиотек, пользователей; загрузка обложек; управление бронированиями.
- Консультант: поиск пользователей, выдача и возврат книг, обращения читателей.
- Поддержка: история сообщений, WebSocket, непрочитанные сообщения, отметка прочтения, закрытие обращения.
- PostgreSQL, транзакции и блокировка строки книги защищают от двойного бронирования последнего экземпляра.
- Адаптация к мобильным устройствам, клавиатурная навигация, диалоги с удержанием фокуса.

## Стек

React 19, Redux Toolkit, React Router 7, TypeScript, Vite 6; NestJS 11, Passport Local, Express Session, Socket.IO; PostgreSQL 16 и TypeORM DataSource. ORM используется для соединений, параметризованных запросов и транзакций; схема хранится в SQL. CSS написан вручную, UI-фреймворк не используется.

Дополнительные инструменты: [Vite](https://vite.dev/guide/), [TypeORM](https://typeorm.io/), [Socket.IO](https://socket.io/docs/v4/), [Docker Compose](https://docs.docker.com/compose/), [Prettier](https://prettier.io/docs/). `fig-kiwi` и `kiwi-schema` используются только вспомогательными скриптами для анализа предоставленного `.fig`.

### Как связаны клиент и сервер

`main.tsx` подключает Redux и маршрутизатор. В `App.tsx` собираются провайдер общих действий, каркас страницы и маршруты. `AppProvider.tsx` запрашивает текущую сессию через `/api/auth/me` и сохраняет пользователя в Redux. Локальные состояния форм, списков и диалогов остаются в соответствующих компонентах и хуках.

Страницы обращаются к REST API через `src/lib/api.ts`. Сервер проверяет сессию, роль и входные данные, затем выполняет параметризованные SQL-запросы. Для бронирования используется транзакция с блокировкой строки книги, чтобы одновременные запросы не забронировали один последний экземпляр дважды. История переписки загружается через HTTP, новые сообщения и обновления поступают через Socket.IO.

В production NestJS обслуживает и API, и собранный клиент с одного адреса. Во время разработки клиент запускается через Vite, который проксирует запросы на сервер.

### Создаваемые и локальные файлы

`dist/` содержит собранный клиент, `dist-server/` — скомпилированный сервер, `node_modules/` — установленные зависимости. Эти каталоги создаются командами установки и сборки и не входят в Git.

Файл `.env` содержит локальные настройки и секрет сессии; он также исключён из Git. При локальном запуске загруженные обложки находятся в `uploads/`, а при запуске через Docker — в именованном томе. На опубликованном сервере включён режим `UPLOAD_STORAGE=database`: обложки хранятся в таблице `uploaded_covers` PostgreSQL.

## Быстрый запуск в Docker

Нужны [Node.js 22+](https://nodejs.org/) и [Docker Desktop](https://docs.docker.com/desktop/).

```bash
npm run setup
docker compose up --build -d
```

Откройте [http://127.0.0.1:3000](http://127.0.0.1:3000). `setup` создаёт `.env` со случайным секретом, если файла ещё нет. Существующие настройки не перезаписываются. Для запуска `setup` установка npm-зависимостей не нужна.

```bash
docker compose logs -f app
docker compose down
```

Обычный `down` сохраняет данные в именованных томах PostgreSQL и uploads. Не удаляйте тома, если нужны сохранённые данные.

## Запуск без контейнера приложения

```bash
npm ci
npm run setup
docker compose up -d db
npm run build
npm start
```

При собственной PostgreSQL настройте `POSTGRES_*` и пропустите команду запуска `db`. При старте сервер идемпотентно создаёт таблицы и индексы из `server/schema.sql`. Переменная `SEED_DEMO=true` добавляет демонстрационные аккаунты и, в пустой каталог, книги. Повторный старт не создаёт дубликатов.

Для разработки:

```bash
npm run dev
```

Фронтенд: [http://127.0.0.1:5173](http://127.0.0.1:5173), API: порт 3000. Vite проксирует `/api`, `/uploads` и `/socket.io` на сервер. В режиме разработки требуется уже собранная серверная часть; скрипт выполняет её начальную сборку и включает наблюдение за изменениями.
